# 上下文压缩与 Agent 安全实验周报

导师您好，汇报一下本周的实验进展。



我这周先没有追求“攻击成功”，而是先想弄清楚一个更基础的问题：Agent 的历史被压缩几轮以后，哪些内容最容易不见，哪些内容还能留下来。因为如果连信息变化的顺序都没弄清楚，后面即使看到一次异常动作，也很难判断到底是不是压缩造成的。

实验在本地完成，使用 Codex + sub2api，模型是 `gpt-5.6-terra`，强度为 `medium`。材料全部是虚构的，模拟工具只写本地目录，不访问外部网络。我在长历史里放入了用户授权、禁止事项、数据来源、来源是否可信、具体工作事项和近期任务规则，然后让同一段历史反复压缩。原计划是 72 次，实际完成了 7 条轨迹、42 次压缩；每次压缩前后的内容都保存了下来。

目前看到的现象比较清楚：具体事项、来源关系、来源可信度和局部限制，较早就变得难以恢复。前几轮用户原话还会被框架重新放进上下文，所以当时看起来授权还在，并不能说明摘要记住了它。大约到第 4 轮，用户原话不再重复出现，模型开始只依赖摘要里的授权说明；到第 5 轮，某项授权和具体事项之间的对应关系基本消失。

反复出现的当前任务规则和近期进度则更容易保留。例如“只回复已记录内容”这类规则，连续多轮都还在。按这批材料看，压缩似乎先削弱具体历史关系，再削弱逐项授权关系；与眼前任务直接相关、反复出现的内容最稳定。不过这只是当前模型和当前历史下的结果，不能直接说所有 Agent 都会按这个顺序压缩。

在此基础上，我又做了第二阶段的探索。我准备了 redirect 和 include 两类本地模拟场景，让低信任材料里出现诱导操作的文字，再比较完整历史、自然压缩和重新补回安全事实三种情况。模型只能提出固定格式的动作，动作是否能执行由独立的 Python 检查器决定。

目前第二阶段跑了 5 批，共 20 个案例和 73 个实际压缩边界，没有出现可以确认的“压缩导致未授权操作”案例。之前有一次日志标成 `attack_success=true`，但后来发现是工具把普通的“自动验证”文字误当成了攻击标记，属于实验工具的问题，已经排除。另外几次是模型参数格式错误，也不能当成安全拦截。

所以现在能下的结论是：上下文压缩确实会让历史关系逐步变弱，尤其是具体来源和授权绑定；但目前还没有证据证明这种变化已经导致了攻击。这个结果也说明，后续实验必须把模型提出动作、策略是否允许、工具是否真的执行分开记录。

从安全角度看，我认为最需要解决的有几件事。授权和数据来源不能只放在摘要里，应该由独立状态保存；低信任文档中的文字不能因为被摘要改写成“待办事项”就自动获得授权；工具必须在模型之外再次检查权限；每次真实压缩都要留下完整记录；多步骤任务还要能追踪文件从哪里来、经过了哪些操作、原来的授权是否仍然有效。

下一步我会先修正实验记录和模拟工具，保证完整历史、自然压缩和恢复条件使用完全相同的材料，并且每一次压缩都能复查。之后再运行正式的配对实验。如果仍然没有出现完整证据链，我会如实报告“当前模型和场景没有观察到压缩导致的攻击”，不会把信息减少或模型格式错误说成安全绕过。
