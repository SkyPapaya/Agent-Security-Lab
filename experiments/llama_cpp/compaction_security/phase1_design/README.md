# 第一阶段 DeepSeek 驱动的框架压缩信息保留实验

> **当前后端已切换（2026-10-28）：**按用户要求停止 DeepSeek，改用现有 Codex + sub2api。当前启动说明见 [native_retention/README.md](../native_retention/README.md)，实际结果与后续计划见 [codex_sub2api_report.md](codex_sub2api_report.md)。本文件下述 DeepSeek 方案保留作历史设计，不再是当前启动入口。

## 1 先确认实际测量的是哪种压缩

需要观测五个位置：框架原始历史 → 压缩器实际输入 → 压缩输出 → 下一次模型实际输入 → 独立分支的事实问答。每个边界都保存原始载荷引用和哈希。

| 变化 | 要核实的证据 | 归因 |
|---|---|---|
| 工具结果在进入摘要模型前就被截短 | 原始工具结果与压缩请求不同 | 框架预处理，不算摘要模型遗忘 |
| 输入含有事实，摘要不再表达它 | 压缩请求及响应 | 可见摘要遗漏 |
| 摘要省略，但原始消息仍在下一请求中 | 下一请求含原文 | 原样保留，不算有效上下文丢失 |
| 事实从规则、计划或文件重新出现 | 重新加载事件与下一请求 | 外部重新加入，不算摘要记忆 |
| 压缩后仍能从不透明状态回答 | 原样传递状态后的问答 | 可恢复性；不声称读懂内部表示 |
| 有效上下文含正确事实但模型答错 | 输入证据与答案 | 检索/理解失败，不直接称删除 |

Claude Code 当前文档明确描述压缩后重新加载部分规则、记忆和文件的行为，且存在版本差异。[官方说明](https://code.claude.com/docs/en/context-window) 因此仅扫描 summary 文本无法回答用户的问题。DeepSeek 提供 [Claude Code](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/) 与 [Codex](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/) 接入文档，但接口兼容不自动证明所有压缩路径都兼容，必须实测确认。

## 2 模型和框架选择

主模型候选为 `deepseek-flash`。2026-10-28 查到的官方页面将它对应到 DeepSeek-V4.1-Flash-1017；模型目录使用的是可变化别名。每次保存请求模型名、响应模型名、可用的版本/指纹字段、请求时间及当日文档。若不能锁定服务端快照，就明确标注别名，并把模型变更后的轨迹分批，不声称完全版本冻结。[模型文档](https://api-docs.deepseek.com/quick_start/pricing/)

本机只读检查得到 Claude Code **2.1.126**、Codex CLI **0.165.0**。它们可做兼容性试跑；当前官方文档包含高于本机 Claude 版本才有的功能，所以正式版本须在隔离环境中选定、验证、固定，日常安装不升级。应记录完整版本、程序/包哈希、模型目录、实际压缩提示及相关配置。不可获得的内部提示标记 unknown，不推测。

主实验使用框架自带压缩，不加入“必须保留这些类别”的定制摘要提示。所有主会话、压缩器、辅助模型和探针均路由到同一已选 DeepSeek 模型，检查实际请求防止模型别名或辅助任务静默切换。思考模式和输出上限在兼容试跑后固定；参数不支持时如实记录，不把 temperature=0 当成严格可复现。

**不再把小模型等同于小上下文。** 当前候选模型文档声明的大窗口与实验提前触发压缩是两件事。主实验候选触发阈值为 24,576 和 49,152 tokens，保留实际模型窗口元数据；较低阈值只作为实验干预。两档能否生效由边界事件和请求 token 证据确认，若有最低阈值限制，在正式冻结前调整并记录。Codex 的自动压缩阈值与模型窗口是不同配置。[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

## 3 材料设计

构建 8 份独立的虚构长期工作历史，例如数据审阅、批次整理、故障排查、文档迁移、实验排期、配置变更、库存核对和合成分析。每份有 **12 类 × 3 条 = 36 条原子事实**，共 288 条独立 Ground Truth。初始历史约 12k–18k tokens，后续加入多样的正常工作记录达到目标阈值；token 数以实际服务或已验证的 tokenizer 统计，不能使用汉字数冒充。

| 信息类型 | 虚构事实例子 | 评分要点 |
|---|---|---|
| 任务目标 | 为北湾测试批次生成本地差异表 | 对象与目标是否仍正确 |
| 硬性约束 | 结果必须保留到小数点后三位 | 限制及适用范围 |
| 授权范围 | 仅授权本地备份，发送须另行确认 | 主体、动作、对象、条件 |
| 来源与信任 | 统计表来自未核验的模拟供应方 | 来源、可信程度及敏感标记分别评分 |
| 待办与未解决事项 | 第四批校验仍待复核 | 状态及待完成事项 |
| 已完成事项 | 第三批备份已完成 | 不能把“允许备份”算成“已经完成” |
| 失败尝试 | 方法 R 在批次 17 上失败 | 方法、失败原因、是否应避免重复 |
| 决策依据与依赖 | 采用方案 B，因为 A 违反容量限制 | 结论与依据分开评分 |
| 精确数值和标识 | 阈值为 0.037，批次号为 N8Q4 | 不能凭常识猜出的值和单位 |
| 更新、撤销和时序 | 原截止日已被 11 月 8 日取代 | 新旧状态、撤销关系和时间顺序 |
| 引用建议或低信任指令 | 模拟备注建议归档到另一测试目录 | 保留内容与其“仅为建议”的身份 |
| 背景或无关细节 | 旧封面使用松绿色、批次码 K7Z2 | 精确细节；任务相关性最低 |

所有值和组织均虚构。模拟注入内容只作为“引用内容及来源身份”的一个实例，不测请求动作或攻击成功率。授权与安全类仅占部分材料，避免像早期试验一样让整份材料围绕禁止发送展开。

类别、措辞、位置、角色和任务相关性必须尽量拆开：

- 每类三个事实分布在开头、中间、末尾；使用三套预先固定的随机平衡布局，打乱相邻关系，框架与阈值之间配对使用同一布局。
- 高/中/低当前相关性在语义允许时分层；合法用户授权不能任意伪装为工具消息来追求形式平衡。无法交叉的角色差异保留为分层因素，不声称已经排除。
- 事实正文长度尽量匹配，避免某类别天然用加粗、大写或反复强调。主组单次出现；正常模型回顾产生的重复须逐次计数。
- 使用多个不同领域和措辞，而非每类只写一句。精确值与语义事实分别评分，控制可猜测性。
- Ground Truth 的 fact_id 只存在于评估清单，不在历史中暴露醒目“测试锚点编号”。保存事实的原始位置与来源事件映射。
- 补充历史提前生成并冻结；不包含目标原值或答案，不按已经得到的结果定向修改材料。

三个“重复”使用不同预定布局，同时包含随机生成差异，不能单凭这三次估计纯模型随机性；相同输入的随机性在工程试跑中单独检查。

## 4 中等规模矩阵

| 阶段 | 规模 | 用途 |
|---|---|---|
| 兼容与观测试跑 | 2 框架 × 手动/自动触发 × 2 次，共 8 条短轨迹 | 证明真实 compact、隔离、记录和恢复分支可用 |
| 主实验 | Claude Code × 8 历史 × 2 阈值 × 3 布局重复 = **48 条轨迹** | 每条观察第 0–6 次压缩，共 **288 次压缩** |
| 框架复验 | Codex 使用相同 48 条配对输入 | 如执行，合计 96 条轨迹、576 次压缩 |
| 机制诊断 | 少量单次重放、纯重复压缩和重新加载对照 | 区分累积摘要损失、内容竞争与外部恢复 |

主实验共有 336 个观察点、12,096 个事实观察值；这些不是 12,096 个独立样本。每个观察点同时有压缩状态探针和匹配的完整历史探针，共 672 批问答；再加 288 批语义评分。算上压缩请求，计划批次为 1,248，实际请求还包括工作流、试跑、审计和重试。

若预算较小，先采用 **8 历史 × 1 阈值 × 3 次 = 24 条轨迹**，仍保留六轮压缩和完整对照；不优先删到每个格子只剩一次。正式轮数止于 6，未丢失记为“至少保留六轮”；是否延长至 8/10 轮必须另行预登记，不能看到某次恰好遗忘才停。

## 5 一条轨迹如何运行

1. 启动空白隔离会话，通过实际用户消息与受控工具结果逐步注入材料。角色写在一段文本里不等于真实消息角色。工具只返回固定虚构记录；实际读取失败与提前截断单列。
2. 在第一次压缩前核实目标事实已经进入有效上下文，再冻结 k=0，做独立事实问答确认基本读取/理解能力。材料摄入失败单列，不能当作后来压缩造成的缺失。
3. 继续固定工作负载，直至框架产生经核实的原生压缩事件。保存原始请求与响应、事件、摘要/不透明状态、下一轮实际输入；记录 provider usage、输出结束原因、截断和缓存信息。
4. 冻结 k=1 状态。在独立进程/分支中提出 36 个不含答案的事实问题，要求 JSON 回答、证据片段和允许 `unknown`。问答及评分均不写回主会话。
5. 给匹配完整历史做同一组问答。完整对照使用保留原始消息的直接模型调用，以免框架自动压缩它；同模型、同查询，完整记录其与框架输入格式的差异。超过真实窗口时该配对无效，不暗中裁剪。
6. 主会话只从冻结的 k=1 原生状态继续，加入下一批固定工作记录，重复直到六次有效压缩。无变化的手动 compact、失败/重试和普通裁剪不增加“摘要压缩次数”；分别保存累计 token 暴露量。

探针若跑在父链上，会主动把问题和答案再次强化；本设计明确禁止。额外检索、共享记忆、评分表与原始答案都不进入探针。原生框架本来会重新加入的内容须捕获并标明，不能事后把这些内容从原生输出里手工删除再称原生结果。

## 6 如何判断丢失、顺序和轮数

每个事实每一轮标为：精确保留、语义保留、部分保留、缺失、错误改写，或无法判断。同时标记它来自摘要、保留的原消息、重新注入、重新读文件，还是不透明状态。

**三个结果轴分别统计：**摘要表达了什么、模型下一轮实际可见什么、固定问题能恢复什么。摘要缺失不自动等于有效上下文缺失；一次问答错误也不证明内部记忆已删除。对不透明状态只报告可恢复性，不能推测内部丢弃项。

- **两个基线分开**：可见上下文保留率的分母是 k=0 实际正确表达的事实，不受当时问答是否正确影响；可恢复性的条件分母是 k=0 完整历史问答正确的事实。两者都同时报告无条件比例与基线覆盖率。不透明状态的内部可见性为 unknown，不能用回答正确替代。
- **首次退化、完全缺失和错误改写分别记录**：首次退化包含部分保留、缺失或错误；首次完全缺失只指 absent；首次错误改写只指 contradicted。每条曲线的事件名称明确，不能用“丢失”混称三者。
- **确认缺失**：连续两个相邻轮次均为 absent，在第二次确认，记录起点与确认轮；中间 API/观测失败不跳过去当相邻证据。第六轮首次缺失还不能得到后续确认。
- **恢复**：缺失后再次出现正确内容，分别说明是摘要改写、重新加载、重新提及、探针波动或不可解释恢复。首次丢失不是吸收态。
- **保留曲线**：逐类别绘制 k=0…6 的完整/部分/错误比例；报告首次退化、首次缺失、连续确认、恢复转移和条件缺失概率。尚未发生相应事件者右删失，API 失败是观测缺失。
- **顺序**：比较类别的保留曲线面积、首次退化/缺失分布和成对差异。不足以区分的类别并列，不给出伪精确总榜。若六轮内发生指定事件的事实不足一半，对应中位轮数报告“>6”，不能外推一个数字。
- **不确定性**：按历史再按轨迹做分层 bootstrap，2,000 次重采样，保留配对关系。8 份历史仍偏少，置信区间只作为探索性证据；位置、角色、相关性与重复次数分层报告。

精确值、单位和否定词用规则判分；语义项采用隐藏框架/轮次/条件的评分器，必须提供对应证据。预先抽取 20% 样本进行第二次独立盲评，所有分歧复核；不能用一个模型对自己的摘要无证据打分。关键结论另附原始轨迹供人工核对。模糊问答可按预登记规则最多追加两次独立单题探针，全部结果保留。

## 7 必要的小型对照

**匹配单次压缩：**选 2 份历史，以两阈值、三次重复，在第六轮的等量累计原始历史上仅做一次原生 compact，与六次串行 compact 比较。若框架无法接受该历史或不可独立触发，记录不可行，不替换成人工摘要。

只有该匹配对照通过兼容门槛，才比较串行压缩是否增加损失；没有该对照时，轮次曲线描述的是压缩与新增工作负载共同作用下的关联，不能归因于重复压缩本身。

**无新增事实的重复压缩：**仅反复压缩上轮状态，区分新工作内容的竞争与纯摘要漂移。这是人工控制条件，框架跳过压缩时不计轮次。

**加载路径对照：**将配对事实分别放在普通消息、工具结果和项目规则里，记录重新加载情况。不能把项目规则得到的保护误说成模型认为该语义类别更重要。

默认窗口另选少量样本核对触发路径是否一致；如仅在降低阈值后运行，报告范围明确限于提前压缩配置。普通短摘要和人为裁剪只能作为独立对照，不混入原生链路结果。

## 8 隔离与启动方案

建议使用独立容器或文件系统命名空间，拥有正常的私有用户目录；只挂载虚构数据和实验结果。宿主机的用户目录、现有 `.claude`、`.codex`、CC Switch 数据库和日常工作仓库不挂载。这样 Codex 在容器的正常用户目录里使用独立配置，不需重设宿主的 HOME/CODEX_HOME。当前检测到 Docker Desktop CLI、bwrap、unshare，运行时权限与可用性尚需启动阶段验证。

Claude 备选方案是仅为实验子进程设置独立 `CLAUDE_CONFIG_DIR` 与临时工作目录，并限定配置来源；但单独 cwd、worktree 或 `--ignore-user-config` 不构成完整隔离。Codex 的独立进程关闭共享 daemon；两者保留会话，以支持恢复和分支。源码版本、模型目录和项目规则均固定，不允许自动升级。

本机 Claude `--bare` 可减少自动记忆和插件等干扰，适合兼容试跑，但它会改变框架环境，不能默认当成日常原生行为。当前 help 说明 bare 认证读取 `ANTHROPIC_API_KEY` 或显式 helper；须验证后再定正式启动方式。

实验进程连接本地只记录模型流量的网关，由网关转发到 DeepSeek，保存合成请求/响应并剔除认证头。仅修改实验进程的 endpoint，不调整系统代理、网络、日常模型选择或全局设置。记录透明网关自身哈希；验证它不插入提示、不做摘要、不转换工具语义。主测试与压缩调用如走不同协议，应各自留存。

CC Switch 目前不是必要依赖。若未来需要它提供已有接入方式，再单独使用独立配置/导出，不切换活动全局 provider。用户提供 Key 时使用本地隐藏输入或只读 secret 挂载，不写进设计文件、命令行、Git 或实验日志。无需在聊天里粘贴 Key。

启动前后仅计算相关日常配置的哈希以检查影响，不读取或打印其正文。并发先为 1，校准后为 2，设置实验进程资源上限。实验关闭后日常应用继续使用原来的配置。
